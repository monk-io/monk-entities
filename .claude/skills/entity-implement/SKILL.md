# Implement Entity Code

Write all source files for a MonkEC entity integration and compile until clean. This skill produces code only — use `/entity-test` for manual testing and `/entity-test-integration` for automated tests.

## Step 1: Gather context

Check for an existing plan:
- Look for `src/<package>/PLAN.md` (created by `/entity-plan`)
- If found, read it — it has API endpoints, entity design, implementation order
- If not found, the user's prompt must provide enough context, or ask for clarification

Read the shared reference files in the `new-entity` skill directory:
- `.claude/skills/entity-new/rules.md` — critical rules, must/must-not, common errors
- `.claude/skills/entity-new/templates.md` — code scaffolds for all file types

Read project conventions:
- `doc/entity-conventions.md` — naming, reserved names
- `doc/scaffold.md` — canonical template
- `doc/common-issues.md` — known pitfalls
- `doc/cost-estimation.md` — pricing API patterns and cost action implementation per provider

Study 1-2 similar existing integrations for patterns (base class, lifecycle, error handling, cost estimation).

For AWS/Azure/GCP, read builtin type definitions in `lib/src/builtins/` before implementing.

## Step 2: Create all files

Create under `src/<package>/`:

```
src/<package>/
├── <package>-base.ts          # Shared base class
├── <entity>.ts                 # Entity implementations (one per file)
├── common.ts                   # Shared types, helpers
├── MANIFEST                    # Module manifest
├── README.md                   # Documentation
├── example.yaml                # Usage examples
└── test/
    └── env.example             # Credential template (minimal)
```

Create the `test/` directory and `env.example` so subsequent skills (`/entity-test`, `/entity-test-integration`) aren't blocked. The full test files (`stack-template.yaml`, `stack-integration.test.yaml`) are generated by `/entity-write-tests` after implementation.

Use templates from `.claude/skills/entity-new/templates.md` as scaffolds. Follow rules from `.claude/skills/entity-new/rules.md`.

Implementation order:
1. `common.ts` — shared types, API key helper
2. `<package>-base.ts` — base class with auth, HTTP client, request helpers
3. Entity classes — simplest first, then dependent ones
4. `MANIFEST`, `example.yaml`, `README.md`
5. `test/env.example` — for cloud builtins (aws/azure/gcp): note that credentials come from `monk cluster providers`; for API-token entities: list required env vars with placeholder values

## Step 3: Register in build system

- **`build.sh`** — add module name to the `modules` array
- **Root `MANIFEST`** — add `dist/<package>` to the DIRS line

Read both files first, add in alphabetical order.

## Step 4: Compile until clean

```bash
INPUT_DIR=./src/<package>/ OUTPUT_DIR=./dist/<package>/ ./monkec.sh compile
```

Fix errors and repeat. Common issues:
- Unused imports → remove them
- Unused parameters → prefix with `_`
- `checkReadiness()` must return `boolean`
- Type mismatches in generics

Typically 1-3 cycles. Do not stop until compilation succeeds with no errors.

## Done

Report to the user:
- Files created (list them)
- Compilation status (success)
- Next step: run `/entity-write-tests <package>` to generate test files, then `/entity-test <package>` for manual testing
