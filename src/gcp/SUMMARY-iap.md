# GCP IAP — Implementation Summary

Adds five GCP Identity-Aware Proxy entities to the `src/gcp/` package.

## Entities

| Entity | Actions | Description |
|--------|---------|-------------|
| `gcp/iap-brand` | `get-info` | Adopts the project's OAuth brand (adopt-only) |
| `gcp/iap-oauth-client` | `get-info`, `reset-secret`, `get-secret` | Creates/manages IAP OAuth clients; writes secret to Monk secret |
| `gcp/iap-settings` | `get-info`, `show-raw` | PATCHes IAP access/application settings on an existing target |
| `gcp/iap-tunnel-dest-group` | `get-info`, `list-cidrs` | CRUD for TCP tunnel destination groups |
| `gcp/iap-access-policy` | `get-info`, `list-members`, `add-member`, `remove-member` | Manages a single `(target, role)` IAM binding |

## Design Decisions

- **Adopt-only brand** — external-audience brands can only be created via Cloud Console; entity lists + adopts.
- **Secret rotation on adoption** — GCP doesn't return IAP OAuth client secrets on GET, so adoption triggers `resetSecret` to ensure the Monk secret is always valid.
- **Prior-settings restore on delete (iap-settings)** — snapshots existing settings before PATCH and restores them on delete, so this entity doesn't nuke settings the user configured outside Monk.
- **Member tracking (iap-access-policy)** — only members added by this entity are removed on delete; pre-existing members are left intact. Multiple instances can safely manage different role bindings on the same target.
- **Target-path builder as shared helper** — `iap-settings` and `iap-access-policy` share the `IapTarget` shape and `buildIapTargetPath()` for the seven supported target kinds (App Engine, Compute global/regional, Cloud Run, project/organization/folder, raw).

## Issues Fixed During Development

- `iap.googleapis.com` missing from `GcpApiServiceName` — added so `gcp/service-usage` can enable it.
- Bare identifiers in YAML `members: [allAuthenticatedUsers]` parsed as runnable refs — quoted to force string literal.
- MANIFEST LOAD order regenerated by compiler — relies on Monk's `requires:` dependency resolution (verified working).
- TypeScript `DeepReadonly<Definition>` mismatch on transform helpers — cast via `unknown` at call sites.
